# GPX2FIT Converter

Forked from [Nick Holloway / fit-route](https://gitlab.com/nwholloway/fit-route), this is an Android app that aims to solve the problem of converting a GPX file to a FIT file for Garmin devices like the Garmin fenix. Then it uses the Android Web Share API to share the FIT file to other apps like [Gadgetbridge](https://gadgetbridge.org/), to send it to a device, completely offline and without the invasive Garmin Connect, that requires internet to send local files to your watch via bluetooth.

It can also be run as a regular website, like the original project, and just let the user download the FIT file.

## Building

Everything is done with `build.sh`, no Android Studio needed. The only requirements are `bash`, `curl`, `tar` and `unzip`, so it works on any Linux distro, including immutable ones like Fedora Silverblue.

The first time, the script downloads everything else into the `.tools/` folder inside the repository (around 2.5 GB, ignored by git):

- [Eclipse Temurin JDK 21](https://adoptium.net/). Capacitor 7 compiles for Java 21, and the Gradle version used (8.13) can't run on JDK 24 or newer.
- [Node.js 22](https://nodejs.org/), for npm and the Capacitor CLI.
- The Android SDK command line tools, plus the platform, build-tools and platform-tools packages (the SDK licenses are accepted automatically).
- The Gradle and npm caches.

The script always uses these copies and ignores any Java, Node.js or Android SDK installed on the system. Nothing is written outside the repository, so deleting the folder (or `./build.sh distclean`) removes every trace.

```console
$ ./build.sh            # debug APK -> dist/gpx2fit-debug.apk
$ ./build.sh install    # build the debug APK and install it with adb on the connected phone
$ ./build.sh release    # release APK -> dist/gpx2fit-release.apk (see below)
$ ./build.sh serve      # run the web version on http://localhost:8080/
$ ./build.sh setup      # only download the tools into .tools/
$ ./build.sh clean      # remove build outputs
$ ./build.sh distclean  # also remove .tools/, node_modules/ and files generated by Capacitor
```

Each build downloads the offline web dependencies (`setup-offline.sh`) if they are missing, installs the npm packages, copies the web app into the Android project (`npx cap sync android`) and builds the APK with Gradle. The debug APK is signed with an automatically generated debug key, so it can be installed directly.

For `serve`, if you want the server exposed on another IP or port, export the variables `C9_IP` or `C9_PORT`.

### Map API key

The map needs a [CARTO API key](https://carto.com/basemaps/apikey) (free for non-commercial use), which is kept out of git. Without it, the map shows "API KEY REQUIRED". Either copy `public/js/config.example.js` to `public/js/config.js` and fill in the key, or pass it to the script, which writes that file for you:

```console
$ CARTO_API_KEY=your_key ./build.sh
```

Note that the key can't be really secret: it's sent with every map tile request, so it's visible in the built app.

### Release builds

A release APK must be signed with your own key. Create a keystore once, using the bundled JDK (keep it safe, outside the repository: you need the same key to install updates over a previous version):

```console
$ .tools/jdk-21/bin/keytool -genkeypair -v -keystore ~/gpx2fit.jks -alias gpx2fit -keyalg RSA -keysize 4096 -validity 10000
```

Then build and sign:

```console
$ GPX2FIT_KEYSTORE=~/gpx2fit.jks GPX2FIT_KEY_ALIAS=gpx2fit ./build.sh release
```

The passwords are asked interactively. To avoid that (e.g. in CI), export `GPX2FIT_KEYSTORE_PASS` and `GPX2FIT_KEY_PASS`. Without `GPX2FIT_KEYSTORE`, the script leaves an unsigned APK in `dist/gpx2fit-release-unsigned.apk`.

### Android Studio

If you prefer it anyway, run `./build.sh` once (it also syncs the web app into the Android project), then open the `android` folder as a project. Run it again after changing the web app, so the changes are copied into the Android project.

## Notes

Documentation of the FIT file format is contained in the FIT SDK  
([download](https://www.thisisant.com/resources/fit/)), and this implementation  
does the bare minimum required.

The mapping uses [CARTO](https://github.com/CartoDB/basemap-styles) raster tiles, which require an [API key](https://carto.com/basemaps/apikey)  
(free for up to 5M requests per month for non-commercial use). See [Map API key](#map-api-key).
